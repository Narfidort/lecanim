# 演出と説明の原則

実際の制作で学習者（定義や証明を読むのが苦手な人）から受けた指摘を，原則としてまとめたもの。
Claude などに制作を任せるときは，この文書を品質基準として必ず読ませる。

対象：定義や証明を読むのが難しく，視覚的なイメージで理解したい学習者。
**「なんとしてでもわからせる」**。スライドの文章を並べてグラフを横に置くだけの動画は失格。

## 0. 構成とトーン

- **モチベ→定義・定理→具体例→証明→まとめ**（`phase()` の既定のキー）は，証明を扱う回のための構成の1つ。
  想定問答・まとめ・実験記録のような回では，無理にこのキーに当てはめず，`phase("好きな見出し", ...)` と，
  見出しの文字をそのまま渡してよい（`PHASES` にないキーはそのまま表示される）。
- **色は「黒・白・青」＋濃淡**：使うのは地（`BG`＝ほぼ黒／`FG`＝ほぼ白／`DIM`/`LINE`）＋構造用の `MAIN`（彩度のある青）
  ＋強調用の `ACCENT`（もっと明るい青。いまいちばん注目してほしい1点だけに使い，箇条書き全部や毎回の強調に乱用しない）。
  色数そのものではなく「色相を増やさない」ことが大事で，濃淡・彩度を変える分には自由。
  `BLUE_E`・`ORANGE_E`・`PURPLE_E`・`YELLOW_E`（`PALETTE`）も青の家族の濃淡違いにしてあり，色分けそのものに意味がある場合
  （Narfi の Fix/Obtain，グラフの彩色，複数系列のグラフなど）の凡例としてだけ使う。
  `GREEN_E`（正しい・合格）・`RED_E`（誤り・警告）だけは例外：✓/✗ のような強い慣習があるので，青の濃淡に押し込めると
  かえって分かりにくい所に限って本物の緑・赤を使ってよい。
- **形は角を立てて細く**：塗りつぶした丸いバッジ・太い縁取りは使わない（`CORNER` は既定 0）。
  枠は細い罫線・ごく薄い塗りにとどめ，太字（`weight=BOLD`）はタイトルや番号など，本当に強調したい所だけに使う。
  数学書のような，淡々として要点にすっと目が行く見た目を目指す（「売り込み」っぽい装飾は避ける）。
- **地の文の変数も TeX で**：`row()` に渡す文字列は，`$...$` で囲まなくても，英字1文字・ギリシャ文字1文字・
  `a_n` のような1文字の下付きを自動で数式として組む（`_SYMBOL_TEX` という検証済みの小さい記号表だけが対象）。
  英単語の内側（`Fix`・`QA` など）では働かないので，書き忘れても崩れない。わざと数式にしたくない1文字（まれ）だけ
  `jp()` を直接使う。

## 1. 証明は「グラフの操作」で見せる

- 頂点を **動かして仕分ける**（`layout_to`）→ **円で囲む**（`blob`）。
- 色を **塗り替える／入れ替える**（`edge_style`, 色の対称性）。
- **全パターンを総当たり**して一覧に ✓ を付ける（2×2×2＝8 通りなど）。
- 道を **一直線に伸ばす**，**切って裏返す**，閉路を **円周に並べ直す**。
- 鳩の巣原理は **印と枠**，数え上げは **点の長方形** や **面積** で見せる。
- 同じ手順を **別の例で繰り返し**，「いつでも通用する」ことを体感させる。
- 条件が足りないと **どこで議論が止まるか**（反例・最良性）を見せる。
- 文字は画面下の字幕1行と，式の項の説明だけ。

## 2. 記号・用語は必ず「指して」から使う

- 初出の記号・用語は `define(記号, 意味, target=指す対象)`：吹き出しで対象を矢印で指し，光らせ，
  画面上部の「記号メモ」に残す。再登場時は `recall()`。
- 矢印が **本当にその物を指しているか** 必ず目視確認する（群の中心が別の要素に当たることがある →
  代表の1要素を target にする）。

## 3. 数式は1項ずつ

- 初出の式・分かりにくい式は `explain([(項, 説明, 色, グラフ上の操作), ...])`。
  式を薄く出し，1項ずつ色付け・括弧・説明。説明と同時に，その項が指すものをグラフ上で数える／光らせる。
- 定義式は内側から説明してよい（`order=` で順番を指定。例：σ₂ は 非隣接ペア → 次数和 → min）。
- 字幕・見出し・まとめの中の数式も `$...$` で書く（自動で TeX 表示）。日本語を `\text{}` に入れない。

## 3.5 証明の記法（`domains.narfi`）

- 記法は使う前に必ず説明する：1行＝1歩，字下げ（枠）＝スコープ，字下げが戻る＝スコープを出る，
  `Fix x | h : φ`（| は「ただし」，`h : φ` は事実 φ の名前），`Obtain`，`choose`，不等式の連鎖，`by`（根拠），∴（スコープを出た結論）。
- 最初のうちは **goal が変わるたびに**「何を取り外して，何が文脈に移り，何が残ったか」を言葉で説明する。
- スコープだけでなく **根拠（justification）** も同じくらい大事：各行で「どの事実を使ったか」を指し，なぜ使えるかを言う。
- 分かりにくい比喩は使わない（「∀ は相手の手，∃ は自分の手」は伝わらなかった）。「∀ の変数は与えられるもの，
  ∃ の変数は自分で作るもの」のように直接言う。

## 3.7 ミニマルに

- 一度にたくさん出さない．注目すべき式は大げさな枠を使わずに提示し，説明は字幕と音声に任せる．
- 証明の表示：スコープは左の細い縦線，文脈 Γ に外枠なし，根拠は Γ の中で大きく表示（吹き出しで証明の行を隠さない），
  ミニマップ・折りたたみは使わない（全体像が分からなくなる）．事実の中身を展開する場所は背景を少しだけ明るくして区別する．
- レイアウトの案は動画を書かずに静止画で比べる（`manim -s` で比較画像を作り，並べて見せる）．

## 3.8 音声と画面の同期

- 「〜します」と言うと同時（または直後）に，その動きを起こす．動きがまとめて読み始めに起こり，音声だけが続く，は不可．
- 説明が 8 秒を超えるなら，文ごとに画面に何かが起こる（光る・出る・動く）ようにする．
- 台本の合図〔名前〕とコードの `cue()` で合わせる（`docs/WORKFLOW.md` 3.5）．合図が遅れる／音声が続くのに動かない，は `lecanim qa` が報告する．
- 書き出す前に `lecanim qa` でエラーを 0 にする．文字の重なり・矢印の不具合・誤読を，視聴者に見つけさせない．

## 4. ナレーション（台本）

- 話者は春日部つむぎ，**アカデミックな発表口調**（です・ます，「では，〜を見ていきましょう」）。
- 字幕の読み上げではなく，**1本の発表として成立する原稿**を書く：主語・助詞・接続詞を省かない，
  「まず／次に／したがって／ここで注目したいのは」で論理をつなぐ。
- 見出しは「次に何をするか」の導入文。まとめは完全な文。
- 非形式的な「＝」は「は」と読む（「ハミルトン閉路 ＝ 円周に並べ替えられる」→「〜は〜」）。
- 記号は読みで書く（ケーろく，アールさんさん，シグマツー，ディーユー）。数字入りの添字は1語のカタカナ（シーニーヨン）。
- 誤読の実例：辺→あたり，値→ね，黄色→おうしょく，出次数→でじすう，強連結→つよれんけつ，
  偶三角形→たま…，鳩の巣→ばとのす，2分の1→にふん，極限値→きょくげんあたい，帯→たい，その和→やわ，
  負の→まけの，十分→じゅっぷん，行→くだり，右上→みぎじょう，アシューム→アシユウム。
  `lecanim check` は既知のパターンしか拾わないので，**新しい台本は `transcripts/` のカナを全文目で読む**。

## 5. 品質

- 具体例は `assert` で検証（主張が正しい例であること，平面描画に交差がないこと）。
- レイアウトは自動 QA（`qa_reports/`）＋コンタクトシートの目視。
- 公開時は VOICEVOX のクレジットを残す。
