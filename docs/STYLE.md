# 演出と説明の原則

実際の制作で学習者（定義や証明を読むのが苦手な人）から受けた指摘を，原則としてまとめたもの。
Claude などに制作を任せるときは，この文書を品質基準として必ず読ませる。

対象：定義や証明を読むのが難しく，視覚的なイメージで理解したい学習者。
**「なんとしてでもわからせる」**。スライドの文章を並べてグラフを横に置くだけの動画は失格。

## 1. 証明は「グラフの操作」で見せる

- 頂点を **動かして仕分ける**（`layout_to`）→ **円で囲む**（`blob`）。
- 色を **塗り替える／入れ替える**（`edge_style`, 色の対称性）。
- **全パターンを総当たり**して一覧に ✓ を付ける（2×2×2＝8 通りなど）。
- 道を **一直線に伸ばす**，**切って裏返す**，閉路を **円周に並べ直す**。
- 鳩の巣原理は **印と枠**，数え上げは **点の長方形** や **面積** で見せる。
- 同じ手順を **別の例で繰り返し**，「いつでも通用する」ことを体感させる。
- 条件が足りないと **どこで議論が止まるか**（反例・最良性）を見せる。
- 文字は画面下の字幕1行と，式の項の説明だけ。

## 2. 記号・用語は必ず「指して」から使う

- 初出の記号・用語は `define(記号, 意味, target=指す対象)`：吹き出しで対象を矢印で指し，光らせ，
  画面上部の「記号メモ」に残す。再登場時は `recall()`。
- 矢印が **本当にその物を指しているか** 必ず目視確認する（群の中心が別の要素に当たることがある →
  代表の1要素を target にする）。

## 3. 数式は1項ずつ

- 初出の式・分かりにくい式は `explain([(項, 説明, 色, グラフ上の操作), ...])`。
  式を薄く出し，1項ずつ色付け・括弧・説明。説明と同時に，その項が指すものをグラフ上で数える／光らせる。
- 定義式は内側から説明してよい（`order=` で順番を指定。例：σ₂ は 非隣接ペア → 次数和 → min）。
- 字幕・見出し・まとめの中の数式も `$...$` で書く（自動で TeX 表示）。日本語を `\text{}` に入れない。

## 4. ナレーション（台本）

- 話者は春日部つむぎ，**アカデミックな発表口調**（です・ます，「では，〜を見ていきましょう」）。
- 字幕の読み上げではなく，**1本の発表として成立する原稿**を書く：主語・助詞・接続詞を省かない，
  「まず／次に／したがって／ここで注目したいのは」で論理をつなぐ。
- 見出しは「次に何をするか」の導入文。まとめは完全な文。
- 非形式的な「＝」は「は」と読む（「ハミルトン閉路 ＝ 円周に並べ替えられる」→「〜は〜」）。
- 記号は読みで書く（ケーろく，アールさんさん，シグマツー，ディーユー）。数字入りの添字は1語のカタカナ（シーニーヨン）。
- 誤読の実例：辺→あたり，値→ね，黄色→おうしょく，出次数→でじすう，強連結→つよれんけつ，
  偶三角形→たま…，鳩の巣→ばとのす。`transcripts/` のカナで必ず確認する。

## 5. 品質

- 具体例は `assert` で検証（主張が正しい例であること，平面描画に交差がないこと）。
- レイアウトは自動 QA（`qa_reports/`）＋コンタクトシートの目視。
- 公開時は VOICEVOX のクレジットを残す。
